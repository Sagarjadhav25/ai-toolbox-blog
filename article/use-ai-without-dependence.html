A Practical System for Using AI Without Losing the Skill

The useful question is not whether to use AI, but which parts of a task should remain yours. If AI performs every difficult step, you may finish faster today while becoming slower tomorrow. A better system deliberately separates thinking, assistance, and verification.

The three-pass method

Pass one is independent work. Spend a few minutes trying the problem, writing an outline, designing the algorithm, or identifying what you already know. Pass two is assisted work. Ask AI for hints, alternative approaches, explanations, or critique. Pass three is verification. Reproduce the result yourself, test it, or explain it without looking at the generated answer.

For studying

Ask for questions before asking for answers. If you are learning databases, for example, write your own SQL query first, then ask the assistant to find edge cases. If you are studying operating systems, explain a concept in your own words and ask the model to identify gaps. This turns AI into a tutor rather than an answer vending machine.

For programming

Keep ownership of architecture and debugging. You can ask for a minimal example, an explanation of an exception, or a review of a function. But run the code, inspect the diff, and understand every dependency you add. For security-sensitive code, perform an additional manual review.

Set friction intentionally

Useful rules include: no AI for the first attempt at a practice question; no copy-paste of code you cannot explain; and no submission of generated academic work without checking the institution's rules. These constraints are small enough to follow and strong enough to preserve learning.

Measure whether AI is actually helping

Keep track of two outcomes: time saved and skill retained. If a workflow saves twenty minutes but leaves you unable to solve the same problem tomorrow, change the workflow. If it removes repetitive formatting while your understanding stays strong, it is doing exactly what an assistant should do.
